# S3-compatible API

Stohr exposes a subset of the S3 API at `/s3`, compatible with AWS clients using the operations listed below. It is a personal-drive interface; Space files are accessed through the web app or REST API.

## Mint an access key

In the web UI: **Settings → Developer → New access key**. The secret is shown **once** at creation — copy it immediately.

Or via the JSON API:

```sh
curl -X POST https://your-stohr.example.com/api/me/s3-keys \
  -H "Authorization: Bearer $STOHR_TOKEN" \
  -H "content-type: application/json" \
  -d '{"name":"laptop"}'
# → { "id": 1, "access_key": "AKIA…", "secret_key": "shhh…", "name": "laptop", "created_at": "…" }
```

## Connect another service

`bun run connect` does the whole handshake in one step: it mints an access key
and prints a token carrying the endpoint, the bucket, and both halves of the key
pair. The other side has one field to fill rather than five to get subtly wrong.

```sh
bun run connect                    # for the first owner account
bun run connect --user wess        # a specific user
bun run connect --name "Inkling"   # label the key (default "Connection token")
bun run connect --url https://files.example.com   # if APP_URL isn't the public URL
```

```
sthc_eyJ2IjoxLCJ1cmwiOiJodHRwOi8vbG9jYWxob3N0OjMwMDEvczMiLCJidWNrZXQiOiJ3ZXNz…
```

The endpoint in the token is `APP_URL` plus `/s3`; the web server passes `/s3`
straight through to the API. The script reads `DATABASE_URL` and `APP_URL` from
the environment (or `.env`), so run it where both point at the install you are
connecting. Both container setups ship it:

```sh
docker exec stohr bun run connect          # single-container image
docker compose exec api bun run connect    # compose.yaml
```

The token is a credential in plain text. It is shown once, should not be
committed, and is revoked by deleting the key from **Settings → Developer**.

[Inkling](https://github.com/wess/inkling) accepts it as `STORAGE_CONNECTION`,
which points its media uploads at this install.

## Use it

The bucket is your **username**. The key is a slash-separated path inside your stohr storage — Stohr auto-creates folders for path components.

```sh
export AWS_ACCESS_KEY_ID="AKIA…"
export AWS_SECRET_ACCESS_KEY="shhh…"
export AWS_DEFAULT_REGION="us-east-1"

# Upload
aws --endpoint-url https://your-stohr.example.com/s3 \
  s3 cp report.pdf s3://wess/reports/q4/report.pdf

# List
aws --endpoint-url https://your-stohr.example.com/s3 \
  s3 ls s3://wess/reports/q4/

# Sync a directory
aws --endpoint-url https://your-stohr.example.com/s3 \
  s3 sync ./build s3://wess/builds/v1.2.3/

# Download
aws --endpoint-url https://your-stohr.example.com/s3 \
  s3 cp s3://wess/reports/q4/report.pdf ./

# Delete
aws --endpoint-url https://your-stohr.example.com/s3 \
  s3 rm s3://wess/reports/q4/report.pdf
```

## Supported operations

| HTTP | meaning |
| --- | --- |
| `PUT /s3/<user>/<key>` | upload object (creates folder hierarchy from key path) |
| `GET /s3/<user>/<key>` | download object |
| `HEAD /s3/<user>/<key>` | metadata + existence |
| `DELETE /s3/<user>/<key>` | remove object |
| `GET /s3/<user>?prefix=<p>` | list (V2) — flat list of all matching keys |

## Quirks

- **Quota** — uploads count against your account's `storage_quota_bytes` cap (0 = unlimited). Over-quota PUTs return `413 EntityTooLarge`.
- **Folders are auto-created** from key path components. `PUT s3://wess/a/b/c.txt` creates folders `a` and `a/b` if they don't exist.
- **Versioning** — re-uploading to the same key archives the previous live version (same as the regular API). The S3 `VersionId` parameter is currently ignored.
- **List** returns a flat list with no `CommonPrefixes` — folder simulation via `delimiter=/` is on the roadmap.
- **S3 multipart upload** is not implemented. Single PUTs are buffered in memory and bounded by `MAX_UPLOAD_BYTES`; size that limit for the available memory. The REST multipart upload endpoint also buffers file bytes and does not remove this memory limit.
- **SigV4** is required. Sign `host` and `x-amz-date`, use credential scope `<date>/<region>/s3/aws4_request`, and keep your client clock within 15 minutes of the server. `UNSIGNED-PAYLOAD` and pre-hashed bodies both work; streaming chunk signatures are unsupported. Reverse proxies must preserve the client hostname through the trusted web proxy.
- **Malware scanning** — with ClamAV configured, object GET is blocked until the blob is clean. Listing and metadata do not deliver file bytes.
- **Account recovery** — changing or resetting your password revokes S3 keys; create a new key and update connected clients.

## Revoking a key

Settings → Developer → Revoke (or `DELETE /api/me/s3-keys/:id`). Anything using that key gets `403 InvalidAccessKeyId` immediately on the next request.
